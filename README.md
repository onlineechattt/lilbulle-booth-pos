# Lil Bulle Booth POS V12.4.0

เพิ่ม Barcode เต็ม / เลข 4 ตัวท้าย / กล้อง / ภาพถ่าย และโหลดเฉพาะข้อมูลของบูธที่เลือก

ชุดนี้ใช้ไฟล์ที่ใช้งานภายใต้ `public/` และ `netlify/functions/` จาก
[`onlineechattt/AI`](https://github.com/onlineechattt/AI/tree/2acf0652c3b71b98c20f0dcc768c7f438d87039a)
commit `2acf0652c3b71b98c20f0dcc768c7f438d87039a` เป็นฐาน ตามคำขอเจ้าของให้ส่งชุดใหม่เข้า repo นี้
ไม่คัดลอกโฟลเดอร์ ZIP ซ้อน `AI-main/AI-main` หรือหน้า GAS ทดลองมาทับระบบคลัง

## สถานะ

- โค้ดพร้อมทดสอบ มี unit/integration tests และ browser smoke test
- ไม่ได้ Deploy Netlify, ไม่ได้อัปเดต Apps Script จริง, ไม่ได้แก้ข้อมูลชีตหรือส่ง LINE จริง
- เก็บไฟล์อ้างอิงที่เจ้าของอัปโหลดเพิ่มไว้ตามเดิม การนำโค้ดเข้าที่นี่ **ไม่เปลี่ยน repo ที่ Netlify ใช้อยู่โดยอัตโนมัติ**
- **POS V12.4 ใช้ `apps-script/BoothPOS_V11.gs` เท่านั้น** ส่วน `BoothPOS_V11.gs` ที่ root และไฟล์ใน handoff ZIP เป็นข้อมูลอ้างอิงรุ่นก่อน ห้ามติดตั้งสองฉบับพร้อมกัน
- ควรสร้าง staging และเทียบกับ Apps Script ที่ deployed จริง ก่อนนำขึ้น production

## วิธีขายด้วย Barcode

1. เลือกบูธและตรวจรับสินค้าตามขั้นตอนเดิม
2. ที่หัวข้อ **สแกน หรือกรอก 4 ตัวท้าย** ทำได้สามวิธี:
   - กรอก Barcode เต็ม 8–14 หลัก หรือเลข 4 ตัวท้าย แล้วกด Enter / เพิ่มสินค้า
   - เครื่องสแกน USB/Bluetooth แบบคีย์บอร์ด: โฟกัสช่องนี้แล้วสแกน ให้เครื่องส่ง Enter ท้ายรหัส
   - กดสแกนด้วยกล้อง หรือเลือกถ่าย/แนบรูปบาร์โค้ด
3. เจอหนึ่งสินค้า เพิ่มหนึ่งชิ้นเข้าตะกร้า เจอเลขท้ายซ้ำหลายสินค้าให้เลือกเอง ไม่เดา SKU
4. ไม่พบรหัสในบูธนี้จะไม่เพิ่มสินค้าจากบูธอื่น กล้องอ่านได้หนึ่งครั้งแล้วหยุด ปิดหน้ากล้อง/สลับแอปก็หยุด
5. การเพิ่มจาก Barcode ยังไม่บันทึกบิล ต้องยืนยันรับเงินเหมือนเดิม ราคากับ EXP ใช้กระบวนการเดิม

Barcode มาจาก `BoothPOS_Products` คอลัมน์ **F: Barcode** ตั้งเป็น **ข้อความธรรมดา** ก่อนกรอกรหัส
เพื่อรักษาเลขศูนย์นำหน้า ห้ามกรอกเพียง 4 ตัวท้ายในชีต ให้กรอกรหัสเต็ม ส่วน 4 ตัวท้ายใช้ค้นหาบนเว็บ
หากเลขศูนย์ถูก Sheets ตัดไปแล้วต้องกรอกรหัสเต็มใหม่ โค้ดไม่เดาศูนย์ที่หายไป
Barcode ระบุ SKU ไม่ระบุ EXP; การจัดล็อตขายตาม EXP ยังอยู่ที่ backend เดิม

## ลดข้อมูลที่อ่านและส่ง

- ก่อนเลือกบูธ อ่านเฉพาะ metadata ที่จำเป็นสำหรับรายการเลือกบูธ ไม่อ่านประวัติขาย รูป หรือคลังกลาง
- หลังเลือกบูธ ใช้ TextFinder จับคู่ `IssueNo` แบบตรงตัว แล้วดึงเฉพาะแถวของบูธนั้นจาก
  `LilbullePOS_V11`, `EventIssue`, `EventReturn`
- TextFinder ยังค้นหาคอลัมน์ใน Sheets ฝั่งเซิร์ฟเวอร์ ไม่ใช่ฐานข้อมูลที่มีดัชนี จึงไม่รับรองว่าจะไม่ค้นผ่านแถวอื่นเลย
  แต่ไม่ขน payload ของบูธอื่นมาอ่าน JSON/รวมยอด/ส่งให้หน้าเว็บ
- `Stock` คลังกลางไม่ถูกอ่านตอนรีเฟรช POS แบบใหม่
- ตารางสินค้าร่วม 5 SKU และราคาชุด/โปรโมชั่นเป็นข้อมูลกลางที่ยังอ่านได้ จากนั้นกรองสินค้าให้ตรงกับบูธ
- โหลดรูปเฉพาะ SKU ของบูธนั้น หลังหน้าหลักพร้อม มี cache เฉพาะ session ตามเดิม
- ไม่เรียก API ทุกครั้งที่พิมพ์/สแกน ใช้ Barcode ที่โหลดมากับบูธแล้ว
- หน้าแรกแสดง 20 บิลล่าสุดของวันนี้ แต่จำนวนบิลและยอดรวมยังรวมทุกบิลที่ไม่ยกเลิก
- ประวัติเต็มโหลดเมื่อกดดู และจำกัดเฉพาะบูธที่เลือก เปลี่ยนบูธที่ dropdown หลักเมื่อต้องดูบูธอื่น
- LINE quota / retry คิวค้างเป็นคำสั่งส่วนกลางที่ผู้ใช้กดเองตามระบบเดิม ไม่โหลดอัตโนมัติตอนขาย/รีเฟรช

## สิ่งที่ต้องติดตั้งสองฝั่ง

### Apps Script เดิม

1. สำรอง Apps Script ที่ deployed จริงและทำสำเนาชีตสำหรับ staging
2. เทียบ extension ปัจจุบันกับฐาน V12.3 ในชุดนี้ โดยเฉพาะหากมีการแก้หลัง commit ที่ระบุด้านบน
3. ใน staging แทนเนื้อหา **extension POS เพียงไฟล์เดียว** ด้วย `apps-script/BoothPOS_V11.gs`
   ชื่อไฟล์เดิมอาจเป็น BoothPOS_V11 หรือ LilBulle_BoothPOS... ให้แทนไฟล์ที่มี `lbApi_` ไม่เพิ่มฉบับซ้ำ
4. **ไม่แทน Code.gs, Index.html หรือ POS_GAS** จาก ZIP เก่า ตรวจว่า `doPost` เดิมมีเส้นทาง `posApi: lilbulle-v11` ไป `lbApi_`
5. ใช้ Script Properties และ schema เดิม ไม่ใส่ PIN/API key/LINE token ใน GitHub
6. โค้ดหลังบ้านนี้ยังรองรับ read contract ของ frontend รุ่นเก่า เพื่อให้ติดตั้ง backend ก่อน frontend ได้
   หน้าใหม่ส่ง `boothScoped: true` ทุก request และตรวจ `scoped: true` ในคำตอบ ถ้า backend ยังไม่รองรับจะหยุดขายและแจ้งให้อัปเดต

### เว็บ Netlify

ไฟล์ที่ใช้งานจริง: `public/`, `netlify/functions/pos.mjs`, `netlify.toml` ที่ root ของ repo นี้
Publish directory = `public`, Functions directory = `netlify/functions`

ตัวแปรฝั่ง Functions ที่ต้องตั้งใน staging/production:

```text
APPS_SCRIPT_URL=<Web App /exec ของ Apps Script ที่ถูกต้อง>
POS_API_KEY=<ค่าจาก Script Properties เดิม>
POS_SESSION_SECRET=<secret ของ session ฝั่ง Netlify>
```

ห้ามวางค่าเหล่านี้ใน `public/` หรือ commit ไฟล์ `.env`
การสแกนกล้องต้องใช้ HTTPS/localhost และอนุญาตกล้อง ไม่มีการขอ microphone
ZXing ที่ใช้กับ browser ที่ไม่มี BarcodeDetector เก็บอยู่ใน `public/vendor/` โหลดเมื่อกดใช้กล้อง/ภาพเท่านั้น
รูปบาร์โค้ดถูกอ่านบนเครื่อง ไม่อัปโหลดเข้าชีตหรือบริการอ่านรหัสภายนอก

## รูป QR รับเงิน

เจ้าของเลือก **ไม่เผยแพร่รูป QR รับเงินใน repo ใหม่นี้** จึงไม่มีไฟล์ QR หรือ URL รูป QR รับเงินในชุดนี้
ปุ่มรับโอนแสดงยอดที่ต้องชำระ และให้ใช้ป้าย QR หน้าบูธ ตรวจยอดเงินจริงเองตามเดิม
การสแกน Barcode สินค้าเป็นคนละส่วนและใช้ได้ตามปกติ

## เติมของ

หน้าใหม่ไม่ดึงสต๊อกคลังทั้งหมดมาเสนอใน POS แล้ว
รายการเติมให้ระบุสินค้าในบูธ จำนวน และ EXP ของที่นำมา โดยเบิกจริงผ่านระบบคลังแยก
การบันทึกเติมใน POS ไม่หัก Stock คลังกลาง และยังต้องตรวจรับของเติมก่อนขาย
การคืนคลังจริงยังอยู่ในระบบคลังเดิม แยก SKU + EXP ตามเดิม

## ทดสอบ

```sh
npm ci
npm test
```

ใน public repo มี 4 checks สำหรับการจับคู่รหัส ศูนย์นำหน้า เลขท้ายซ้ำ SKU ต่างบูธ และ proxy/requestId
ส่วน GAS ledger fixture tests อีก 6 checks ได้รันในเครื่องแล้ว แต่ไม่เผยแพร่ไฟล์ fixture เนื่องจากระบบตรวจอนุมัติปฏิเสธการเผยแพร่
ครอบคลุมการอ่านแถวแยกบูธ ยอดรวมแม้แสดงเพียง 20 บิล scope รูป/ประวัติ การขาย/ยกเลิก/ปิดวันตาม EXP และ compatibility กับ client เก่า

Browser smoke (เสริม): ติดตั้ง Playwright สำหรับการทดสอบ หรือกำหนด `LILBULLE_PLAYWRIGHT_MODULE`
ไปยัง package Playwright ที่มีในเครื่อง และ `LILBULLE_CHROME` ถ้าต้องใช้ Chrome executable ที่มีอยู่

```sh
node tests/browser-smoke.mjs
```

Browser test ใช้ server/ข้อมูลจำลอง ไม่ติดต่อ Apps Script จริงหรือ LINE จริง
ทดสอบ EAN-13 ภาพสังเคราะห์ผ่าน ZXing และกล้องจำลองด้วย canvas MediaStream รวมทั้งกรณีไม่อนุญาตกล้อง
**ยังต้องทดสอบกล้องและบาร์โค้ดสินค้าจริงบน iPhone/Android ก่อน production**

## Rollout / rollback

1. ทดสอบกับ Sheet/GAS สำเนา และ staging site ที่ชี้ไปสำเนาเท่านั้น
2. เช็ก sale → retry request เดิม → void → closeDay → คืนของจริงแยก EXP / เติม-ตรวจรับ / สลิป / QR / LINE preview-send
3. อนุมัติแล้วจึงอัปเดต Apps Script extension ก่อนเว็บ Netlify และรีเฟรชเครื่องขายเพื่อโหลด `app.js?v=12.4.0`
4. ถ้าต้อง rollback ให้ rollback frontend ก่อน backend เพราะ frontend ใหม่นี้ต้องการ backend ที่รองรับ scoped contract
5. บิลที่บันทึกแล้วไม่ต้องคีย์ซ้ำ ไม่ย้อนชีตทับยอดที่ขายจริงไปแล้ว การ rollback เป็นการย้อนโค้ดเท่านั้น
